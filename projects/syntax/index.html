The problem
Phrase had no design system and one product designer. Every team rebuilt the same buttons, selects and empty states, each a little different.
The work
I started Syntax, got it a developer, and grew it with the engineers into tokens, components, a contribution model and versioned releases.
The result
Every core Phrase product runs on it, and teams insert its components 150k+ times every six months.

ContextEvery screen looked like Phrase, and none looked like each other

When I joined Phrase in 2020, I was the only product designer and there was no design system. Teams built the same components again and again. Designers redrew the same select every sprint; engineers copied the last button they could find. The goal was one shared language, made as a shortcut people would choose, not a rulebook they had to follow.

The approachStart with a few buttons, then earn the next step

Syntax began with buttons, inputs and selects, each with guidance on when to use it and which states it has, and accessible defaults built in so nobody had to remember them. At first it was a one-person job. The first real step was convincing leadership to give it a developer. From there the team grew to two designers and three engineers, and Syntax moved from spare-time maintenance to funded product infrastructure with its own engineering owners.

The systemThe Figma file and the code say the same thing

Syntax grew into design tokens, a component library, a contribution model and versioned releases with release notes. The Figma components matched production code, so a change in the file was ready to ship. Around it grew a shared way of working across squads: handoff, design QA, and release news, with the pages and analytics for each release set up together with the engineers.

TodayFrom one designer to twelve

Six years in, every core Phrase product runs on Syntax. The design team around it grew too, from one designer to twelve, through hiring, onboarding and mentoring two designers at a time. The hardest part was never the first version. It was making the second version the obvious next step.
